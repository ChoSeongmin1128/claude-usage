# Codex 로그인과 사용량 조회

ClaudeUsage는 `~/.codex/auth.json`을 CLI 소유의 읽기 전용 입력으로 사용합니다. 앱이 refresh token을 직접 교환하거나 새 자격을 파일에 쓰지 않습니다. CLI에서 계정을 바꾼 뒤 앱을 새로고침하면 현재 로그인과 사용량을 다시 확인합니다.

## 조회와 인증 복구

- 요청을 시작할 때 자격 파일을 백그라운드에서 읽습니다. 파일 교체·삭제·손상과 같은 수정 시각을 유지한 변경도 확인합니다. 화면 렌더링은 마지막으로 검증한 메모리 상태를 사용합니다.
- 사용량과 한도 초기화 크레딧 요청에 같은 자격과 계정 헤더를 전달합니다. 응답이 제공하는 계정 ID도 대조합니다.
- 자격이 만료됐거나 API가 인증을 거부하면 공식 Codex CLI의 stdio app-server 경로에서 인증을 갱신하고 동일 계정의 숫자 quota를 확인합니다. 계정 읽기와 quota 조회는 [공식 app-server 문서](https://learn.chatgpt.com/docs/app-server#auth-endpoints)의 API를 사용하며 대화·모델 실행을 만들지 않습니다.
- 복구는 한 번의 사용자 조회에서 최대 한 번이며 API·CLI·재시도·크레딧 보충이 30초 예산을 공유합니다. CLI 프로세스 종료·회수에는 별도로 최대 1.2초의 정리 대기를 둡니다.
- CLI를 찾지 못하거나 필요한 계정 식별 응답을 지원하지 않으면 해당 경로를 사용하지 않습니다. CLI 설치·업데이트·로그인 상태를 확인한 뒤 다시 시도해야 합니다. 다른 앱의 계정이나 인증 저장소로 전환하지 않습니다.

## 계정 변경과 표시

파일에서 확인한 자격에 메모리 세대를 부여하고 같은 세대의 동시 요청만 공유합니다. 파일이 바뀌거나 로그아웃하면 이전 계정 수치를 숨기며 이전 요청의 성공·실패를 현재 화면에 적용하지 않습니다. 조회 중 변경은 남은 시간 안에서 한 번 다시 확인합니다.

같은 계정의 일시적 통신 실패에는 마지막 성공 데이터와 확인 시각을 유지합니다. 숫자 사용량 필드가 없거나 형식이 달라진 응답은 0%로 표시하지 않습니다. 취소된 작업은 로그인 실패로 바꾸지 않습니다.

## 저장과 진단

- 기존 CLI 파일 형식을 마이그레이션하거나 별도 계정 선택 목록을 만들지 않습니다.
- 토큰과 자격 지문은 메모리에서만 다루며 로그·UserDefaults·진단 화면에 남기지 않습니다.
- 오류는 고정된 원인 코드로 구분하고 원본 인증 응답을 출력하지 않습니다.
- 앱이 직접 시작한 CLI의 프로세스 그룹만 정리합니다. 사용자가 실행한 다른 CLI·앱은 종료하지 않습니다.

## 검증

가짜 파일과 응답으로 로그인 교체, 늦은 응답, 요청 공유, 취소, 시간 제한, 잘못된 quota와 프로세스 종료를 검사합니다. 배포 전에는 공식 CLI에서 실제 갱신과 계정별 quota를 별도로 확인합니다. 실제 계정 전환은 사용자가 로그인하고 자동 테스트가 계정 경합을 보완합니다.

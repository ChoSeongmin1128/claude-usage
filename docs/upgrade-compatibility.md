# 업데이트 호환 안내

## 2.5.1의 설정 이전

중간 버전을 실행하지 않아도 기존 설정과 계정 자료를 현재 형식으로 이전합니다.

- 연결 설정 v1·v2·v3는 v4로 직접 이전하며 idle timeout을 보존합니다.
- 기존 Google 연결과 이메일 고정은 조회에 사용하지 않습니다. 제품을 알 수 없는 이전 설정은 CLI 또는 독립 앱을 한 번 선택하도록 안내합니다.
- 명시적인 이전 `agy_cli` 선택은 CLI로 보존합니다. 현재 로그인은 선택한 제품에서 확인하며 다른 제품으로 자동 전환하지 않습니다.
- 쓰기와 다시 읽기 검증이 끝나야 이전 완료로 기록합니다. 실패하면 원본을 복구하고 재시도할 수 있습니다.
- OAuth 자격증명 저장 형식, Claude·Codex 계정, 팝오버·메뉴바·알림 설정은 이번 변경으로 초기화하지 않습니다.
- 과거 자격증명을 읽는 데 별도 권한이 필요하면 기존 대화형 이전 안내를 사용합니다. 인증 취소 후 자동 조회가 같은 요청을 반복하지 않습니다.

2.5.0 이하 앱은 새로운 조회 대상 설정 형식을 이해하지 못합니다. 구버전으로 되돌릴 때 현재 설정을 임의로 삭제하거나 새 형식을 구형 값으로 덮어쓰지 않습니다.

## 2.6.0의 표시·알림 설정 이전

- 기존 사용자는 ‘기존 선택 유지’로 시작해 서비스별 표시와 알림 문구를 유지합니다. 공통 표시 기준에서 사용한 양·남은 양을 선택하면 메뉴바·팝오버·알림에 함께 적용됩니다. 신규 설치의 기본값은 남은 양입니다.
- 이전 알림 숫자는 당시의 사용·남음 기준으로 해석해 실제 알림 시점을 보존합니다. 예를 들어 남음 15%와 사용 85%는 같은 조건이며 표시 전환으로 알림 시점이나 활성 상태가 달라지지 않습니다.
- 이전 알림 설정은 보존하고 새 형식에는 한 번만 변환해 저장합니다. 다시 실행해도 숫자가 다시 뒤집히지 않습니다.
- 배터리·원형 등 스타일 변경과 표시 기준은 별도 선택입니다. 알 수 없는 사용량은 0%나 100%로 바꾸지 않습니다.

- 한도별 알림 선택은 첫 정상 조회에서 기존 Claude 5시간·주간 선택, Codex 기본 한도, Antigravity의 기존 유효 대상을 이전합니다. 조회가 없거나 사용할 수 있는 수치가 없으면 이전을 미룹니다.
- 새 모델·한도는 알림을 자동으로 켜지 않습니다. 일시적으로 미제공된 항목의 선택은 보존하며, 계정이 바뀌면 이전 계정의 조회 목록과 알림 이력은 사용하지 않습니다. 알림 임계값은 공통으로 유지합니다.
- 이름·표시 순서·초기화 시각이 바뀌어도 같은 상위 ID와 주기의 선택은 유지합니다. 식별 정보가 부족하거나 충돌하는 항목은 표시하되 알림 선택을 제한합니다.

## 배포본별 업데이트 경로

공개 ZIP 51개의 메타데이터를 조사한 결과입니다. 배포본이 가진 실제 앱 식별자와 feed를 기준으로 하며, 태그 이름만으로 채널을 판단하지 않습니다. 이 조사는 실제 설치 성공을 대신하지 않습니다.

| 배포본 계열 | 앱 식별자·업데이트 경로 | 검증 및 지원 원칙 |
|---|---|---|
| 운영 feed를 사용하는 2.0.x~2.4.13 | 운영 식별자 → 운영 feed, Sparkle 2.8.1 | 2.4.13→2.5.2 실제 업데이트·재실행·조회·설정 보존 확인. 그보다 오래된 배포본은 별도 macOS 환경에서 실설치 검증 필요 |
| 2.4.5~2.4.14 staging | staging 식별자 → staging feed, Sparkle 2.8.1 | ZIP 기반 이전 설치본에서 현재 서명된 DMG 업데이트를 확인 |
| 2.4.15·2.5.0 staging | staging 식별자 → staging feed, Sparkle 2.10.0 | 서명된 feed를 요구하는 설치본의 실제 업그레이드 확인 |
| 초기 staging 및 일부 2.1.x·2.2.x 배포본 | 운영 식별자 → staging feed | 현재 staging과 앱 이름·식별자가 다르므로 일반적인 동일 앱 업데이트로 취급하지 않음 |

조사한 배포본의 최소 macOS 버전은 14.0이며 Sparkle 공개키는 같습니다. 과거 2.3.3의 build 값은 `20330`이므로 현재 버전 공식으로 과거 build를 재계산하지 않습니다.

초기 혼합 채널에 해당하는 정식 태그는 2.1.2~2.1.5이며, 2.1.6·2.2.0·2.2.1 및 2.4.3 이하의 staging 배포본도 같은 경로를 사용합니다. 현재 앱 코드는 이미 배포된 구버전의 feed 주소를 실행 전에 고칠 수 없습니다.

이 경우 자동 업데이트 성공을 보장하지 않습니다. 원하는 채널의 공식 DMG를 수동 설치하는 복구 경로를 사용하되, 운영 설정을 staging에 자동 복사하지 않습니다. 운영 사용자는 검증된 운영 후보가 게시된 뒤 같은 운영 앱 식별자의 설치본으로 이동해야 합니다. staging 게시를 운영 배포로 간주하지 않습니다.

## 완료 판정

다음 검증을 구분해 기록합니다.

1. 공개 배포본의 메타데이터·업데이트 경로 조사
2. 과거 저장 형식의 직접 이전, 중단·재시도·원본 보존 자동 테스트
3. 실제 구버전 앱에서 다운로드·검증·설치·재실행
4. 첫 실행 후 계정 선택·사용량·설정 보존과 다음 업데이트 확인

별도 환경에서 수행하지 못한 운영 구버전 실설치는 미검증으로 남깁니다. 최신 버전의 숫자를 낮추거나 다른 앱 식별자로 다시 서명한 빌드를 실제 구버전 검증으로 계산하지 않습니다.

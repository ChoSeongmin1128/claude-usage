# Claude 연결과 사용량 조회

ClaudeUsage는 Claude 웹 세션과 Claude Code OAuth를 지원합니다. 사용자가 선택한 계정의 자격과 응답 계정을 대조하며, 다른 계정의 사용량을 섞지 않습니다.

## 연결 방법

### Claude Code

장기 사용에는 Claude Code OAuth를 권장합니다.

```bash
brew install --cask claude-code
claude auth login
```

ClaudeUsage 설정에서 Claude Code 계정을 선택합니다. Claude Code가 로그인을 Keychain에 두면 Claude Code와 같은 도구(`/usr/bin/security`)로 읽어 확인 창 없이 현재 로그인을 씁니다. Claude Code에서 로그인 계정을 바꾸면 다음 조회부터 반영됩니다.

Claude Code를 한동안 쓰지 않아 토큰이 만료돼 있으면 앱이 직접 갱신하지 않고 Claude Code가 스스로 갱신하게 합니다(`claude -p /usage`, 모델 호출 없음). 이 도구로 읽지 못하는 환경에서만 `Claude Code 다시 연결`이 macOS 인증을 요청합니다.

웹 로그인을 메뉴바에 쓰고 다른 Claude Code 계정을 함께 조회하지 않으면 그 계정의 토큰을 갱신하지 않습니다. 실제 Claude Code 계정을 조회할 때 실행 파일을 찾지 못하면 로그인 만료와 구분해 안내합니다. 터미널에서 `claude`가 실행되는지 확인한 뒤 앱을 다시 여세요.

### 브라우저에서 가져오기

기본 브라우저나 Claude 앱에서 `claude.ai`에 로그인한 상태라면 `브라우저에서 가져오기`를 사용할 수 있습니다. 기본 브라우저를 먼저 보고, 그다음 Claude 앱과 설치된 다른 브라우저를 봅니다. 앱은 Claude 세션 쿠키만 가져오며 전체 쿠키 문자열을 저장 대상으로 사용하지 않습니다.

- Chrome, Brave, Edge, Whale, Vivaldi, Chromium, Claude 앱: 처음 가져올 때 macOS가 그 브라우저의 Safe Storage 항목을 쓸지 한 번 묻습니다. "항상 허용"을 누르면 다시 묻지 않습니다.
- Firefox: 쿠키를 암호화하지 않아 확인 창이 없습니다.
- Safari: 쿠키 파일을 읽으려면 전체 디스크 접근 권한이 필요합니다. 가져오기 창에서 설정을 열 수 있습니다.
- Arc는 Safe Storage 키를 로그인 Keychain에 두지 않아 가져올 수 없습니다. 앱에서 로그인을 사용합니다.

로그인이 어디에 있는지 미리 볼 때는 쿠키 이름과 만료 시각만 읽고 값은 읽지 않으므로 확인 창이 뜨지 않습니다. 브라우저에 로그인이 없으면 `브라우저에서 로그인`이 기본 브라우저로 `claude.ai`를 열고, 로그인이 끝나면 가져오기를 시작합니다.

### 웹 로그인

브라우저 가져오기가 동작하지 않으면 앱의 웹 로그인 창에서 `claude.ai`에 로그인할 수 있습니다. 로그인 완료 후 필요한 세션 값만 추출합니다.

### 수동 sessionKey

고급 설정에서 `sessionKey` 값만 직접 입력할 수 있습니다. 전체 쿠키 문자열을 붙여넣지 마세요.

## 조회 경로

- 웹 계정은 `claude.ai` 사용량 API를 조회합니다.
- Claude Code 계정은 Anthropic OAuth 사용량 API를 조회합니다.
- 명시적으로 선택한 계정에는 다른 경로의 자격을 섞지 않습니다.
- 자동 조회는 검증 상태와 최근 성공 경로를 참고하지만 응답 계정이 다르면 결과를 버립니다.
- 함께 표시하는 다른 Claude Code 계정도 같은 자격으로 계정과 사용량을 확인합니다. 조회 도중 로그인 자료가 바뀌면 해당 응답을 적용하지 않고 계정을 다시 확인합니다.

Messages 응답 헤더를 이용한 보조 경로는 구형 설정 호환을 위해 내부에 남아 있습니다. 현재 설정 화면에는 이를 켜거나 수동 실행하는 기능이 없고 신규 설치에서는 꺼져 있습니다.

## 자격과 개인정보

자격증명은 macOS Keychain, Claude Code 저장소 또는 ClaudeUsage 전용 보안 저장소에서 필요한 범위만 읽습니다. 토큰·쿠키·원본 인증 응답은 진단 화면이나 운영 로그에 기록하지 않습니다.

ClaudeUsage가 관리하는 사본을 정리하더라도 Claude Code가 소유한 로그인 자료를 삭제하지 않습니다. 이전 버전 자료의 이전이 실패하면 원본을 보존하고 다시 시도할 수 있게 합니다.

## 표시와 알림

일시적인 통신 실패에는 마지막으로 성공한 사용량과 확인 시각을 유지합니다. 로그인 계정이 바뀌거나 계정 불일치가 확인되면 이전 계정의 수치를 숨깁니다.

API의 `resets_at`은 고정 리셋 시각이 아니라 현재 사용량 창의 갱신 예상 시각으로 표시합니다. 사용량 알림은 시각 변경이 아니라 사용률이 설정한 임계값을 넘는 상태 전이를 기준으로 보냅니다.

## 추가 사용량과 초기화권

추가 사용량은 해당 계정·조직의 사용량 응답 본문을 우선 사용합니다. 금액과 한도를 임의로 고정하지 않으며 본문이 없는 웹 응답에서만 별도 조회를 사용합니다.

초기화권의 개수를 확인하지 못하면 0개로 처리하거나 신규 관측값을 지우지 않습니다. 활성 여부를 먼저 판정해 중지·시작 전·만료된 지급 항목은 제외합니다. 첫 확인은 기준값이며 이후 실제 증가나 확인 가능한 새 지급만 신규로 표시합니다.

## 문제 해결

- Claude Code 로그인이 만료됐으면 `claude auth login` 후 앱에서 `Claude Code 다시 연결`을 실행합니다.
- 브라우저 가져오기가 실패하면 그 브라우저의 `claude.ai` 로그인 상태를 확인하거나 웹 로그인을 사용합니다.
- 계정을 바꾼 뒤 이전 수치가 숨겨진 상태라면 새로고침해 새 계정의 확인된 응답을 기다립니다.
- 인증을 취소한 경우 자동 조회가 같은 인증 요청을 반복하지 않습니다. 사용자가 다시 연결을 시작해야 합니다.
